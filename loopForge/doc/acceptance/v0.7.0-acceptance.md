# loopForge v0.7.0 验收清单 — Skills

## 1. 版本范围与目标

本清单验收 **v0.7.0 Skills** 能力（见 `doc/log/progress-v0.7.0.md`），包括：

| 能力 | 说明 |
|------|------|
| 载体与注册 | `SKILL.md`（YAML front matter + 正文）、`SkillRegistry.LoadFromPaths`、校验与重名策略 |
| 注入 | 默认 **Base system → MCP 片段（预留）→ Skills**；Variable 块行为不变 |
| Runner | `WithSkillRegistry` / `WithSkillPath`、与 `Agent` 的接线 |
| 可选工具 | `execute_shell_script`、`load_skill`（受配置与 `LoopState` 约束） |
| 观测 | `slog`、OpenTelemetry（`loopforge/skill`） |
| 集成演示 | 仓库内 **`test-server/`** 提供 HTTP + 前端，用于手工验收 **Runtime**（SSE、工具列表、system 内容） |

## 2. 自动化验证（引擎）

在 **`loopForge/`** 模块根目录执行：

```bash
go test ./... -count=1
```

**预期**：全部包测试通过。重点包括：

- `pkg/skill`：front matter 解析、重名策略（先出现的条目保留）、`scriptPathUnderBundle` 路径安全。
- `pkg/runner`：`WithSkillPath` 加载 `SKILL.md` 并将 `## Skill: …` 注入系统提示（`TestRunner_WithSkillPath_InjectedIntoSystem`）。

可选：

```bash
cd ../test-server && go build ./...
```

## 3. 引擎功能检查项

1. **注册表加载**  
   - `skill.NewRegistry()` + `LoadFromPaths(ctx, []string{rootDir})`；每根目录下可发现 `**/SKILL.md`。  
   - `Get(name)` 返回的 `SkillSpec` 含非空 `ContentHash` 与 `SourcePath`。

2. **Agent 注入顺序**  
   - 未设置 `SystemPromptBuilder` 时：**`SystemInstructions` → MCP 占位 → skills**（`skill.ComposeSystemSegments`）；启用 `WithVariable` 时其后追加 Variable 块。

3. **Runner 接线**  
   - `WithSkillPath` 惰性加载并缓存；`Agent.SkillRegistry` 为 nil 时注入。  
   - `LoadFromPaths` 失败时，事件流上出现 `invalid_config`。

4. **可选工具**  
   - `WithSkillShellTool(true)` + `SkillRegistry`：注册 `execute_shell_script`。  
   - `WithLoadSkillTool(true)`：仅当 `LoopState != nil` 时注册 `load_skill`；追加 `LoopState.ExtraSkills` 并在后续 step 合并进 system。

5. **可观测性**  
   - skill 装载与 registry 完成时 `slog` INFO。  
   - OTel：`loopforge/skill` 下 `skill.registry.load`、`skill.parse` 等 span（无 SDK 时为 noop）。

## 4. 集成验收：test-server（v0.7.0 手工 / 联调）

仓库 **`test-server/`** 依赖 `replace loopforge => ../loopForge`，用于在浏览器中验证 **与版本相关的 Runtime 表现**（非替代第 2、3 节的单元测试）。

### 4.1 前置与启动

- Go 与 `test-server/go.mod` 一致；真实 LLM 需配置 `LARK_API_KEY` 等。  
- 启动：`cd test-server && ./start.sh` 或 `go build -o ./bin/test-server . && ./bin/test-server`；默认 **`ADDR`** 为 `:8191`。

### 4.2 Skill 资源与扫描

- 内置示例：**`test-server/skills/demo/SKILL.md`**（名 **`demo`**），脚本 **`scripts/hello.sh`**（可转发至 **`hello.py`** 观察 `argv`）。  
- 扫描来源：**`LOOPFORGE_SKILL_PATH`** + 当前工作目录 **`./skills`**。

| 验收项 | 通过标准 |
|--------|----------|
| 注册表 | `GET /api/runtime-config` 中 `skill_loaded` 为 true，列表含 `demo` |
| 重载 | `POST /api/skills/reload` 返回 200，`generation` 合理更新 |

### 4.3 HTTP API（可不调用 LLM）

| 方法 | 路径 | 用途 |
|------|------|------|
| GET | `/api/skills` | 已加载 skill 元数据 |
| GET | `/api/runtime-config` | 路径、加载状态、generation、列表 |
| POST | `/api/skills/reload` | 重新扫描装载 |

验收：JSON 正常；非法路径等错误返回明确 `error`（允许 5xx）。

### 4.4 前端运行时命令（`:` 前缀，不调 LLM）

| 命令 | 预期 |
|------|------|
| `:help` | 显示命令说明 |
| `:list` | 展示 `/api/skills` 结果 |
| `:reload` | 调用 reload 并刷新页眉状态 |

### 4.5 Skill 调试模式（调 LLM，验收版本注入与工具）

1. 选择 **「Skill 调试」**（`skill_debug: true`，运行仍为单 Agent）。  
2. 填写 **API Key**。  
3. **注册 execute_shell_script**（默认建议勾选）：请求含 `skill_shell: true`，`call_llm_start.tools` 中含 **`execute_shell_script`**。  
4. 可选 **展示 system prompt**：SSE 中可见完整 system，且含 **`## Skill: demo`**。  
5. 让模型调用 `execute_shell_script`，典型参数如：  
   `{"skill":"demo","script":"scripts/hello.sh","args":["a","b"]}`  
   工具输出中含 **`argv`**（经 `hello.py`）。

| 验收项 | 通过标准 |
|--------|----------|
| Skill 注入 | system 中出现 `## Skill: demo` |
| shell 工具 | `skill_shell: true` 时 tools 含 `execute_shell_script` |
| 脚本执行 | 调用 `scripts/hello.sh` 成功，输出含传参信息 |

**说明**：**Single / Transfer** 在 `test-server` 中对 Skill 的挂载方式一致（`buildSingleAgent` 与 `buildTransferEntry` 共用 `appendSkillRuntimeOpts`）。验收 Skill 时可关闭 MCP 或保持默认，避免工具列表干扰判读。

### 4.6 边界（不阻塞 v0.7.0 版本通过）

- `execute_shell_script` 以 **`/bin/sh`** 执行入口；需 **Python 时用 shell 包装**（如 `.sh` 调用 `python3`），不验收「引擎直接执行 .py」。  
- `load_skill` 依赖 **Runner + LoopState**；无 `LoopState` 的 `Agent.Run` 路径可能不注册（与引擎一致）。

## 5. 本文档不覆盖的后续项

- MCP `prompts/list` 与 `MCPPromptFragment` 实装。  
- `SkillBundleManifest` 强校验。  
- 非 shell 的多运行时 `Executor`（设计中的可选增强）。

### 6.5 小结

- **主线（发现、注册、注入、观测、shell 工具、验收与 design 指针）**：与进度稿 **v0.7.0 交付清单**一致，已覆盖。
